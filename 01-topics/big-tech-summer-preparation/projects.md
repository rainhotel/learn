# 项目规划

## 主项目：Java Agent Task Runtime

### 项目定位

构建一个面向长任务的 Agent 执行运行时，而不是普通聊天机器人。系统接受任务，规划并调用受控工具，持久化执行轨迹，在失败或重启后恢复，并对并发量、超时和危险操作进行治理。

这个项目同时服务三项目标：证明 Agent Runtime 理解、补强 Java 并发、展示传统后端可靠性。

### 推荐技术栈

- Java 21、Spring Boot
- MySQL 或 PostgreSQL：任务、步骤、事件与幂等记录
- Redis：限流、短期状态或分布式协调，只在确有需要时使用
- CompletableFuture/ThreadPoolExecutor；增加虚拟线程对照实验
- Micrometer + Prometheus/Grafana，或最小化指标端点
- Testcontainers、JMH、k6/JMeter

### MVP 模块

1. Task API：提交、查询、取消、重试任务。
2. Runtime：任务状态机、步骤执行、超时、取消和错误分类。
3. Tool Registry：工具 schema、权限等级、幂等属性和调用审计。
4. Persistence：事件与检查点持久化，支持进程重启恢复。

### 第二阶段能力

- 有界队列、租户并发配额和背压。
- 指数退避、重试预算、熔断和补偿。
- Planner/Executor 或固定工作流与动态规划的对照。
- 危险工具人工审批和上下文隔离。
- 执行 trace、延迟、成功率、队列深度和 token/成本指标。

### 明确不做

- 不为“像大项目”而拆十几个微服务。
- 不先做复杂前端，最小管理页或 Swagger 足够。
- 不自研向量数据库、消息队列或工作流引擎。
- 不把所有 Agent 概念一次性塞入 MVP。

### 核心演示场景

“研究并生成技术报告”任务：搜索/读取若干受控材料，抽取信息，生成结构化结论；其中一个工具故意超时或失败，系统执行重试、降级或人工审批，并在重启后继续任务。

### 必须产出的证据

- 架构图和任务状态机图。
- 一个最小运行控制台，覆盖任务提交、状态、执行轨迹和审批操作。
- 3 条 ADR：线程模型、持久化模型、重试/幂等策略。
- 压测报告：吞吐、P95、队列深度、拒绝数、资源使用。
- 5 个故障实验：超时、部分失败、重复请求、进程重启、下游限流。
- 单元测试、接口测试和一条端到端浏览器测试。
- 一段 3-5 分钟演示视频或可复现演示脚本。

## 旧项目强化：微信公众号内容系统

- 补齐线程池参数、队列容量、超时、失败率、重试次数和批次规模证据。
- 画清楚批量上传的 DAG：上传、聚合、草稿组装、补偿。
- 写出外部 API 限流、部分失败和幂等的真实边界。
- 若没有历史数据，使用可复现实验数据，明确标注为压测结果而非线上数据。

## 旧项目强化：CampusBites

- 重点保留真实用户、登录审核链路和 Redis 排名设计。
- 补齐榜单更新策略、缓存一致性、热点 key 和内容审核失败处理。
- 不把它包装成高并发系统，优先展示从 0 到 1 和产品交付能力。
