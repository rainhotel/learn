# 跨层系统设计哲学 Formula Sheet

## Little's Law

- 表达式：`L = λW`
- 含义：系统平均在途任务数 = 平均到达率 × 平均停留时间。
- 用途：连接并发量、吞吐与响应时间，检查容量估算是否自洽。
- 边界：使用长期稳定平均值；不能单独预测高分位延迟和饱和后的非线性行为。

## Average Cache Access Time

- 表达式：`Tavg = H × Thit + (1 - H) × Tmiss`
- 含义：平均成本由命中路径和 miss penalty 共同决定。
- 用途：判断缓存是否真正降低总成本。
- 边界：未显式反映热点、回源并发、失效成本和长尾。

## Availability Composition

- 串联系统近似：`Aseries = Π Ai`
- 独立并联冗余近似：`Aparallel = 1 - Π(1 - Ai)`
- 用途：理解依赖越多端到端可用性越低，独立冗余为何有用。
- 边界：真实故障往往相关，不能假设副本完全独立。

## Utilization

- 表达式：`ρ = λ / μ`
- 含义：到达率与服务率之比。
- 用途：识别系统是否接近饱和。
- 边界：实际系统有多阶段、不同请求成本和服务时间方差；`ρ < 1` 不代表延迟可接受。

## Retry Amplification

- 粗略上界：调用链每层最多尝试 `r` 次、深度 `d` 时，下游尝试可能接近 `r^d`。
- 用途：解释为什么多层独立重试会放大故障。
- 方法：一层主导重试、整体 Deadline、Retry Budget、退避与 Jitter。

## Exponential Backoff With Jitter

- 上限：`cap_n = min(max_backoff, base × 2^n)`
- Full Jitter：`sleep ~ Uniform(0, cap_n)`
- 用途：避免失败客户端同步重试。
- 边界：退避不能修复不可重试错误，也不能替代幂等和容量限制。

## Quorum Intuition

- 常见条件：`R + W > N`，且需要根据模型考虑 `W > N/2`。
- 用途：理解读写集合相交。
- 边界：集合相交不自动证明线性一致；版本、Sloppy Quorum、并发写和恢复都会影响语义。

## Error Budget

- 允许失败比例：`1 - SLO`
- 例：月度 99.9% 可用性，错误预算约为 0.1%。
- 用途：在可靠性和变更速度之间建立量化约束。
- 边界：必须先定义正确 SLI 和统计窗口。

## Recovery Objectives

- RPO：最多允许丢失多少时间范围的数据。
- RTO：故障后多久恢复到目标服务水平。
- 用途：指导复制、备份、PITR、演练和容量投入。
- 边界：文档中的目标不等于真实能力，必须恢复演练验证。

## Universal Scalability Law

- 形式：`C(N) = N / (1 + α(N-1) + βN(N-1))`
- 含义：串行化成本 `α` 和一致性/协作成本 `β` 限制扩展性。
- 用途：形成“增加并发不必然增加吞吐”的定量直觉。
- 边界：它是拟合和推理模型，不替代真实瓶颈分析。

## Decision Methods

### Concurrency Control Selection

1. 能否消除共享状态？
2. 能否按 Key 划分单所有者？
3. 数据库约束或原子 SQL 是否足够？
4. 冲突低时是否适合 OCC？
5. 冲突高且临界区短时是否适合锁？
6. 是否真的需要跨进程协调？
7. 若使用租约，资源端能否验证 Fencing Token？

### Overload Selection

1. 最贵的工作在哪一步发生？
2. 能否在昂贵工作前拒绝？
3. 哪类流量优先保护？
4. 是限制速率还是限制并发？
5. 队列上限和等待上限是多少？
6. 降级是否依赖同一个故障组件？
