# 面试追问与表达

## 1. HashMap 的底层结构是什么？

先说明版本：JDK 21 当前实现是数组桶，桶内使用链表或树节点。再解释这属于实现，不是 Map 接口规范。

## 2. put 流程是什么？

回答主线：hash -> 初始化 -> 索引 -> 空桶/相等 key/树/链表 -> 更新或新增 -> 树化判断 -> 扩容判断。

### 追问

- key 相等如何判断？
- null key 放在哪里？
- 为什么先比较 hash？

## 3. 为什么容量是 2 的幂？

讲索引按位与、分布与扩容拆分。不要只回答“位运算快”。

## 4. 什么时候树化？

JDK 21 当前实现：插入使桶达到相关阈值并且 table 容量至少 64 时树化；容量不足时优先扩容。避免简单回答“长度大于 8”。

## 5. 为什么负载因子默认 0.75？

官方 API 将它描述为时间和空间成本的良好折中。不要伪造一个严格数学最优证明。

## 6. equals 和 hashCode 有什么关系？

相等必须同 hash；同 hash 不必相等。覆盖 equals 通常必须覆盖 hashCode。结合实验说明查询失败。

## 7. HashMap 为什么线程不安全？

讲数据竞争、可见性、复合操作和结构修改，而不是只背某个历史 JDK 的死循环故事。

## 8. ConcurrentHashMap 如何保证线程安全？

根据后续并发章节回答当前 JDK 实现。此章先讲公开语义：读取通常不阻塞、给定 key 的更新与观察值读取之间的 happens-before、弱一致迭代和原子复合方法。

## 9. HashMap、LinkedHashMap、TreeMap 如何选？

从是否需要顺序、何种顺序、操作复杂度和内存开销回答。

## 10. initialCapacity 怎么设置？

已知期望 mappings 时 JDK 21 可使用 `HashMap.newHashMap(expectedMappings)`。手工构造需结合负载因子。容量不是越大越好，因为占用空间和迭代成本增加。
