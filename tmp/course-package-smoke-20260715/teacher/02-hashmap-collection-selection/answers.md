# 练习答案与评分标准

## A. 契约与基础

### 1

- key 不重复，每个 key 最多一个 value。
- Map 接口不统一保证顺序，具体实现决定。
- null 是否允许由实现决定。

### 2

equals：自反、对称、传递、一致、非 null 对 null 返回 false。

hashCode：相等对象必须相同；参与 equals 的信息未改变时，同一运行中应保持一致；不相等对象可以碰撞。

### 3

插入位置由旧 hash 决定，修改后查询使用新 hash 定位，导致条目仍在旧桶但无法正常找到。

## B. 源码推演

### 1

计算 hash -> 初始化 table -> 定位桶 -> 空桶插入 / 首节点比较 / 树插入 / 链表遍历 -> 更新或追加 -> 可能树化 -> size 超阈值扩容。

### 2

便于用 `(n - 1) & hash` 定位，并使扩容翻倍时根据一个 hash 位完成桶拆分。

### 3

table 较小时，碰撞可能来自容量不足。当前 JDK 21 在 table 容量小于 64 时优先扩容，以减少碰撞；树节点空间成本更高。

### 4

容量翻倍新增一个地址位。节点对应 hash 在 oldCap 位为 0 时保留，为 1 时移动到 `index + oldCap`。

## C. 容量

### 1

JDK 21 可使用 `HashMap.newHashMap(1000)` 直接表达预期 mapping 数。也可结合负载因子手动计算，但应注意实现取整与上限。

### 2

构造参数是初始容量语义，默认阈值约为容量乘 0.75；内部容量还会调整到 2 的幂。

### 3

占用更多数组空间，并增加遍历成本；官方文档说明迭代与 capacity + size 相关。

## D. 选型

1. 固定 enum 渠道：EnumMap，构造完成后可包装为不可修改 Map。
2. 插入顺序：LinkedHashMap。
3. 并发频次：ConcurrentHashMap + LongAdder。
4. 范围查询：TreeMap 或更持久化的数据库有序索引，取决于数据生命周期和规模。

## E. 故障与编码

### 1

检查 key 的 equals/hashCode 和修改历史；改用不可变值对象或只使用稳定 ID 作为 key，重新构建已损坏 Map。

### 2

ConcurrentHashMap 场景使用 `computeIfAbsent`，但 mappingFunction 仍应避免外部不可重复副作用。若需要跨数据库/网络的唯一创建，应使用更强的业务幂等机制。

### 3

满分要求：能够运行、记录 JDK/参数、说明反射观察是实现细节，并避免由单次实验推出稳定阈值保证。

## 加分题

官方 API 指出并发更新时 size 等聚合方法反映瞬时状态，适合监控或估计。完成判断需要显式任务状态、计数协议、Latch/Phaser 或持久化状态机。

## 评分

- 90-100：可以进行源码和项目答辩。
- 80-89：主体掌握，补做容量或并发题。
- 60-79：重新运行契约实验并复述 put 主路径。
- 低于 60：返回 Map 契约与 key 设计部分。
