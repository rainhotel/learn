# 第 20 章 Teach-back：教会别人写一份守得住的简历

## 5 分钟：为什么先建事实台账

讲清：简历句子不是起点；原始事实、来源、证据和边界才是起点。用一个“把后学 Redis 写进实习”的反例说明来源污染。

## 15 分钟：从经历到三类简历

现场把一条事实依次变成：

1. 完整 STAR/CAR。
2. 90 秒口述。
3. 一条 bullet。
4. Java 后端版排序。
5. Agent 后端版排序。
6. 制造业数字化版排序。

强调只有选择和顺序变化，事实、角色、技术与数字不变化。

## 30 分钟：量化与证据诊所

让听众带来五条带数字的简历句子，逐条检查：

- 指标是什么？
- 基线和结果是什么？
- 环境、版本和样本是什么？
- 谁执行、谁记录？
- 原始证据在哪里？
- 有哪些限制？

无法回答时演示三种处理：补证据、降级措辞、删除数字。

## 45 分钟：逐句面试压力测试

选择一版完整简历，按“归属 -> 实现 -> 取舍 -> 证据 -> 反事实”追问。至少包含：

- 一条大烨实习 claim。
- 一条独立项目 claim。
- 一条性能或比例 claim。
- 一条 Agent/RAG claim。
- 一条设计中或 Pending 的能力。

将结果标记 Green/Yellow/Red，并现场修订至少三条。

## 教学演示禁区

- 不展示真实密钥、公司内部域名、客户数据和未经许可的代码。
- 不提供“包装实习技术栈”的示范答案。
- 不把版式技巧描述为保证通过 ATS。
- 不用虚构数字演示“优秀成果”；可以使用明确标记为虚构的反例，但不能进入成品。
- 不以“精通”替代能力证据。

## 同伴评分表

| 检查项 | 通过条件 |
|---|---|
| 事实链路 | 能从 bullet 回到 fact_id 和 evidence_ref |
| 来源边界 | 实习、独立项目、课程实验、设计完全区分 |
| 量化 | 六元组完整，限制明确 |
| 岗位适配 | 三版有选择差异但事实不冲突 |
| ATS | 关键词来自带日期 JD 且有证据 |
| 面试防守 | 能回答实现、取舍、失败和反事实 |
| 合规 | 无泄密、个人信息和虚假归属风险 |

## Teach-back 验收

- 至少一名陌生听众能复述事实台账方法。
- 听众能指出三条来源污染或量化问题。
- 讲授者能在质疑下主动降级不成立的 claim。
- 有录屏或结构化反馈，且已据此修订讲义或简历。
- 未真实完成陌生听众试讲前，本章保持 Teach Pending。
