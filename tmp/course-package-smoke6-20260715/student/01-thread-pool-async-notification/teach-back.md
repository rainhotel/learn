# Teach-back 试讲与复盘

## 5 分钟试讲

### 目标

让听众理解线程池不是“线程复用器”，而是资源边界。

### 结构

1. 通知接口同步发送为什么危险。
2. 核心线程、队列、最大线程、拒绝的决策路径。
3. 无界队列为什么隐藏过载。
4. NotifyFlow 为什么先持久化再执行。
5. 一句话总结：线程池参数必须由业务容量和失败策略共同决定。

### 必画图

```text
core -> queue -> max -> reject
```

## 15 分钟试讲

### 0-2 分钟：问题

描述 1,000 个接收方、供应商慢调用和 QPS 限制。

### 2-6 分钟：机制

讲解执行决策、三类队列和拒绝策略。

### 6-10 分钟：工程设计

讲参数推导、限流、连接池、渠道隔离和监控。

### 10-13 分钟：可靠性

讲持久化、拒绝、超时、中断和关闭。

### 13-15 分钟：实验与总结

展示 `ThreadPoolLab` 三个实验结果，说明观察到什么、不能从实验推导什么。

## 试讲自检

- [ ] 没有把最大线程误讲成核心线程满后立即创建。
- [ ] 没有把线程数公式说成标准答案。
- [ ] 能解释 CallerRuns 的调用上下文风险。
- [ ] 能解释 `shutdownNow` 为什么不能保证停止。
- [ ] 能解释 Future 超时与底层 I/O 超时的区别。
- [ ] 能说明虚拟线程仍需资源边界。

## 听众追问题

请听众随机选择：

1. 如果任务有依赖，队列策略会有什么风险？
2. 如果供应商响应越来越慢，哪个指标最先变化？
3. 为什么线程池不能替代 MQ？
4. 如果不能丢任务，为什么还使用拒绝策略？
5. 线程池能否运行时扩容？什么时候扩容无效？
