# 面试追问与表达

## 1. InnoDB 为什么需要主键？

主键通常是聚簇索引，直接承载行数据；二级索引包含主键，主键越长会放大二级索引。没有合适主键时 InnoDB 会生成隐藏聚簇索引，但业务应显式定义稳定主键。

## 2. 联合索引怎么设计？

从真实查询的等值条件、范围条件、排序、返回列、选择性和写入代价推导。结合 NotifyFlow 的 tenant/status/time 查询，而不是背“最左匹配”一句话。

## 3. 覆盖索引是什么？

查询所需列都在二级索引中，可避免回表。代价是索引更宽、写维护和空间更高。

## 4. EXPLAIN 看什么？

实际 key、扫描行数、过滤、排序、访问类型、是否回表/覆盖、估算与实际偏差。必要时使用 EXPLAIN ANALYZE。

## 5. MySQL 默认隔离级别是什么？

InnoDB 默认通常是 REPEATABLE READ。回答时注意服务器版本和配置；不要把所有数据库默认值混为一谈。

## 6. MVCC 是什么？

通过多版本和 Read View 为一致性读提供快照，不等同于所有读都不加锁；更新和锁定读仍会取得锁。

## 7. RR 和 RC 区别？

RR 事务内一致性读通常复用首次快照；RC 每次一致性读新建快照，锁与非匹配记录释放行为也不同。

## 8. 如何设计消息任务领取？

短事务 + 有索引的待处理查询 + `FOR UPDATE SKIP LOCKED` + 写入 worker/lease/version，提交后外部调用，条件回写和超时恢复。

## 9. 为什么不能把事务包住远程调用？

远程延迟和失败会长时间占锁、连接和事务资源，增加阻塞和死锁；数据库也不能回滚外部副作用。

## 10. 如何处理死锁？

捕获 1213、回滚当前事务、有限次数退避并重试整个事务；统一锁顺序、缩短事务、加索引、避免大范围更新。

## 11. 项目中如何保证幂等？

数据库 `(tenant_id, request_id)` 唯一约束作为最终保障，重复键返回已有任务；消息消费和供应商调用还要有独立幂等键。
