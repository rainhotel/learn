# 第 22 章面试问题与结构化回答

## 1. 拿到算法题第一分钟做什么？

复述问题并确认输入输出、规模、重复值、顺序、是否允许修改输入、空值和溢出。用一个小样例验证理解，再开始方案讨论。

## 2. 为什么先说朴素解？

朴素解建立正确性基线，暴露性能瓶颈，也为随机差分测试提供 oracle。它不应占满时间，但直接跳到背过的模板会让推导和迁移能力不可见。

## 3. 两层循环一定是 O(n²) 吗？

不一定。要计算指针总移动次数。滑动窗口中 left 和 right 都只单调前进，合计常为 O(n)；若内层每次从头扫描才可能达到 O(n²)。

## 4. HashMap 操作为什么不能无条件说 O(1)？

通常是期望或摊还 O(1)，依赖哈希分布、负载因子、扩容和冲突。Java 在特定条件下会树化冲突桶，但不能把所有失败模型省略成“绝对 O(1)”。

## 5. ArrayDeque 为什么常用于栈和队列？

它提供双端 O(1) 摊还操作，避免旧式 `Stack` 的遗留同步设计，也通常比链表有更好的局部性。它不允许 null，因此 null 不能用作业务元素或哨兵。

## 6. 如何避免二分死循环？

先固定区间语义，再保证每个分支严格缩小区间。中点写 `left + (right-left)/2`；对 `[left,right)` 使用 `left<right`，更新通常是 `left=mid+1` 或 `right=mid`。

## 7. 滑动窗口的本质是什么？

维护一个连续区间及其增量状态，使右边扩展和左边收缩都可低成本更新。只有当约束允许指针单调移动时才能得到线性复杂度。

## 8. 前缀和为什么经常与哈希结合？

区间和可表示为两个前缀和之差。若要找满足某个差值的历史位置或计数，哈希表可快速查找所需前缀。累计值可能超过 int，应评估 long。

## 9. 反转链表最容易犯什么错？

修改 `current.next` 前没有保存原 next，导致未处理后缀丢失。解释时应给出 previous、current 和 next 分别代表什么。

## 10. 单调栈解决哪类问题？

它维护尚未找到答案的元素，并在新元素破坏单调性时批量结算，常用于下一个更大/更小元素和直方图边界。每个元素最多进出栈一次，因此常为 O(n)。

## 11. 堆和排序如何选择？

一次性需要完整有序结果时排序更直接，O(n log n)。数据流或只需 Top K 时，大小 K 的堆可做到 O(n log K) 和 O(K) 空间。还要考虑输出是否需要最终有序。

## 12. DFS 和 BFS 的选择依据？

无权图最短步数通常用 BFS；遍历所有节点、递归结构或回溯搜索可用 DFS。两者时间都可能是 O(V+E)，差别在访问顺序、空间峰值和递归栈风险。

## 13. 图遍历何时标记 visited？

BFS 通常在入队时标记，避免同一节点被多个前驱重复入队。DFS 可在进入节点时标记。检测有向图环时需三色状态，单个 visited 不足以区分“当前递归路径”和“已完成”。

## 14. 拓扑排序失败说明什么？

若处理节点数少于总节点数，图中存在有向环，无法形成完整拓扑序。它只说明依赖顺序，不代表任务权限、安全和副作用已经处理。

## 15. 并查集适合什么，不适合什么？

适合动态合并集合和查询连通性，路径压缩加按秩/大小合并具有近常数摊还复杂度。不直接提供具体路径或最短距离。

## 16. 树递归怎样避免“会写不会讲”？

先用一句话定义函数参数和返回值，再说明 base case、左右子问题为何规模更小、如何组合。最后讨论树高导致的递归栈空间。

## 17. 回溯中的撤销为什么必要？

path 是共享可变状态。递归返回后必须恢复到进入本层前的状态，才能探索兄弟分支。输出时还需复制 path，否则所有结果可能引用同一对象。

## 18. 动态规划五要素是什么？

状态定义、转移方程、基础状态、遍历顺序、最终答案位置。还应说明不可达状态和空间压缩是否会破坏尚未使用的依赖。

## 19. 如何证明贪心正确？

常用交换论证：把任意最优解的第一个不同选择替换成贪心选择，证明结果不变差，然后归纳处理剩余问题。只说“局部最优得到全局最优”是结论，不是证明。

## 20. Java 比较器为什么不建议相减？

两个 int 或 long 相减可能溢出并产生错误符号，破坏比较器的传递性。使用 `Integer.compare`、`Long.compare` 或组合比较器。

## 21. 字符串题用 char 有什么限制？

`char` 是 UTF-16 code unit，不保证等于一个 Unicode 字符。若合同包含补充平面字符或用户感知字素，应使用 code point 或更高层文本规则，并说明复杂度口径。

## 22. 如何系统测试算法边界？

按结构、值域、分布、答案位置、图树形态、状态和规模建立矩阵。先手写最小反例，再用小规模朴素解做随机差分；随机测试不能代替证明。

## 23. 溢出只发生在最终答案吗？

不是。中点、前缀和、乘法、比较器相减、计数和哨兵加一都可能溢出。应在运算前提升到 long，而不是溢出后再赋给 long。

## 24. 原地算法一定更好吗？

不一定。它降低辅助空间，但可能修改调用方数据、增加实现风险并降低可读性。必须先确认输入可修改以及并发或共享语义。

## 25. 如何解释摊还复杂度？

单次操作可能昂贵，但一系列操作的总成本受限。例如动态数组偶尔扩容 O(n)，连续 n 次追加总成本仍为 O(n)，所以平均到每次为摊还 O(1)。

## 26. 看过答案后重做算独立完成吗？

不算首次独立完成。应保留首次状态为 reviewed/hinted，闭卷间隔重做可记录 recall pass。诚实的状态区分比一个漂亮的完成率更有价值。

## 27. 为什么复习题不重复计入题量？

题量衡量不同首次输入的覆盖，复习衡量长期提取能力。混合计数会让同一题多次重做看起来像扩大了知识覆盖。

## 28. Teach-back 如何验证而不是表演？

让读者只依赖讲义完成一个非同题变式，并观察其行为。记录停顿、错误和任务结果，作者不即时补充。能否迁移比“听懂了”反馈更可靠。

## 29. 模拟面试成绩怎样才可信？

需要固定时间、陌生题、统一量表、提示记录、原始代码或录像和评审人。单次高分、熟题演练或自评分都不能代表稳定能力。

## 30. 算法如何迁移到后端工程？

先映射合同和规模，再问数据是否在单机内存、多实例如何一致、故障如何恢复、是否有数据库或中间件原语。面试算法是机制训练，不可直接包装成生产方案。

## 31. 面试中卡住怎么办？

说出已确认的事实、尝试过的方案和具体阻塞点，构造更小示例，回到朴素解或不变量。收到提示后复述提示并说明它改变了哪一步推理。

## 32. 代码写完后最后五分钟做什么？

用正常、最小、重复/边界和极端值样例 dry run；检查 null 合同、下标、循环终止、long、可变对象复制；最后总结复杂度和替代方案。

## 33. 80-100 题为什么只是路线而非保证？

题量能约束覆盖，但不能证明长期记忆、陌生迁移、代码正确性和面试沟通。本章用复习、测试、白板、Teach-back 和模拟面试补足这些维度。

## 34. 如何回答“刷了多少题”？

给出截止日期和统计口径，区分 attempted、independent pass 和 recall pass，并能指向证据。如果尚未完成，直接说明当前进度和主要短板，不预测最终数字。

## 35. 如何判断可以进入真实面试？

不是只看题量。应综合到期复习债务、无补全编码稳定性、边界测试、三轮陌生模拟的错因趋势和表达能力；任何数字都必须来自已完成记录。
