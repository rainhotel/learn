# 第 21 章练习：闭卷口述、追问树与模拟面试

## 使用规则

- 第一轮必须闭卷、计时、录音或转写。
- 先提交自己的回答，再解锁参考答案。
- 每道题标记证据 ID；没有运行证据时写明设计或 Pending。
- 不允许把课程项目改写成实习事实。
- 单题建议先做 90 秒版本，再按追问延长到 180 秒。

## A. 闭卷机制题

### 1. volatile 与 happens-before

用 90 秒回答：

- volatile 能保证什么？
- 为什么 volatile value++ 仍可能丢失更新？
- 在 NotifyFlow 中分别给出一个适用和不适用场景。
- 指出一份可引用证据。

### 2. 线程池饱和

解释 ThreadPoolExecutor 接收任务的顺序，并回答：

- 为什么无界队列会让 maximumPoolSize 长期不生效？
- CallerRunsPolicy 的反馈作用和风险是什么？
- 哪些指标证明系统已经饱和？

### 3. 中断、取消与虚拟线程

解释 Java 中断为何是协作式协议。比较：

- Future.cancel(true)。
- shutdownNow()。
- 超时返回。
- Java 21 虚拟线程。

说明为什么它们都不能自动取消已经发生的外部副作用。

### 4. JVM 事故分类

场景：Pod P99 上升、CPU 95%、heap 使用率 60%、没有明显 OOM。

给出：

1. 至少三个竞争假设。
2. 证据采集顺序。
3. 止血与验证。
4. 为什么不能直接回答“加大堆”。

### 5. Spring 事务失效

给出一个同类自调用导致声明式事务未生效的调用链。说明代理为什么没有拦截，以及三种修复方式的代价。

### 6. MySQL 任务领取

为多个 worker 领取待发送任务设计查询与事务边界，讨论：

- 联合索引。
- FOR UPDATE SKIP LOCKED。
- 小批处理。
- 崩溃后接管。
- 死锁重试与幂等。

### 7. Redis 故障

NotifyFlow 同时使用 Redis 做模板缓存、限流和短期幂等加速。Redis 不可用时，三种用途分别采用什么策略？哪些事实绝不能只放在 Redis？

### 8. Kafka、Outbox 与 exactly-once

回答：

- 为什么先写 MySQL 再发 Kafka 有双写窗口？
- Outbox 解决什么，仍没有解决什么？
- offset 提交与 Provider 调用怎样产生重复或 UNKNOWN？
- 可以安全承诺到什么程度？

### 9. 网络超时

Provider 已接收请求，但响应在网络中丢失。解释：

- connect、read 和 overall deadline 的区别。
- 为什么本地 timeout 不等于 Provider 失败。
- 如何使用 idempotency key、UNKNOWN 和 reconciliation 恢复。

### 10. Docker/Kubernetes 下线

设计 NotifyFlow Worker 的优雅下线：

- readiness 如何变化？
- 何时停止领取？
- 怎样处理 in-flight？
- termination grace 与应用 deadline 如何配合？
- 为什么 liveness 不应依赖所有下游都健康？

### 11. RAG 质量定位

用户说“回答错了”。给出一个分阶段排查树，至少覆盖：

- ingestion/version/ACL。
- sparse/dense retrieval。
- rerank/context。
- generation/citation/refusal。
- 评测与线上证据。

### 12. Agent 工具安全

设计一个“查询过去 15 分钟邮件积压原因”的只读 Tool，并说明：

- schema、身份、租户和时间窗。
- timeout、最大返回量和审计。
- prompt injection 如何隔离。
- 为什么 Agent 不能直接执行 replay。

## B. 追问树作业

### 13. 并发追问树

以“synchronized 和 ReentrantLock 怎么选”为根问题，至少画四层、十二个节点。必须包含可中断获取、Condition、异常释放、性能误区和项目证据。

### 14. 数据一致性追问树

以“怎样保证通知不重复”为根问题，展开到 API 幂等、Outbox、Kafka 重复、Provider timeout、回调乱序、对账和人工重放。

### 15. RAG/Agent 追问树

以“为什么要做 Agent，而不是普通工作流”为根问题，展开到决策自由度、Tool、Memory、状态机、权限、评测、成本和多 Agent。

### 16. 证据追问树

从“你说线程池出现容量拐点，怎么证明”开始，展开到环境、负载模型、指标、原始输出、替代解释、限制和复现。

## C. NotifyFlow 项目答辩

### 17. 三档项目介绍

分别录制 90 秒、3 分钟和 8 分钟版本。三个版本必须保持需求、个人贡献、证据和 Pending 边界一致。

### 18. 事实与证据审计

从自己的项目介绍中抽取全部动词和数字，建立表格：

| 表述 | 类型 | 证据 ID | 当前可用 | 安全措辞 |
|---|---|---|---|---|

类型只允许：实习事实、独立项目运行、确定性模型、静态设计、后续计划。

### 19. Provider UNKNOWN 事故

写出一条完整时间线：

1. Provider 保存请求。
2. 响应丢失。
3. 客户端 timeout。
4. 本地进入 UNKNOWN。
5. 查询/回调/对账。
6. 最终状态收敛。

同时给出一个错误实现和验证“没有重复副作用”的数据正确性查询思路。

### 20. 性能数字追问

面试官问“项目 QPS 是多少、优化了多少”。在没有 NotifyFlow 端到端压测证据的前提下，完成一个诚实且有技术含量的两分钟回答。

### 21. 十倍流量

假设创建峰值、扇出和 Provider P99 同时增加。不要直接回答“扩容”，先列：

- 新的容量计算。
- 可能的五个瓶颈。
- 观测证据。
- 分阶段演进。
- 防止恢复风暴的预算。

### 22. 删除组件

分别回答删除 Redis、Kafka、Agent 后系统怎样变化。说明哪些需求仍可满足，哪些能力降低，什么时候更简单的方案更合适。

### 23. 先进制造迁移

将 NotifyFlow 改造为设备告警和工单通知平台。完成需求澄清、状态机、边缘断线、事件时间、高优先级隔离、权限和 Agent 边界设计。

## D. 模拟面试与纠错

### 24. 40 题闭卷抽测

从 interview.md 中跨八个能力域抽取 40 题。每题 90 秒，使用 10 分制评分。记录：

- 首答分。
- 追问后分。
- 错误标签。
- 证据定位耗时。
- 48 小时复训分。

### 25. 45 分钟综合模拟

建议结构：

- 8 分钟 Java/JMM/并发/JVM。
- 8 分钟 Spring/MySQL/Redis/Kafka。
- 5 分钟网络/容器/排障。
- 10 分钟 NotifyFlow。
- 6 分钟 RAG/Agent。
- 8 分钟系统设计追问。

保存完整题目、转写、评分和评审意见。

### 26. 纠错卡

从模拟面试中选择五个不同类型错误，为每个错误制作一张纠错卡。不得只写“下次注意”。

### 27. 延迟复训

在 48 小时和 7 天后，随机改变场景重答同一机制。例如将线程池问题改为虚拟线程、将短信 Provider 改为设备网关。比较迁移能力，而不是背原句。

### 28. 反向追问

为目标岗位准备五个向面试官提问的问题，覆盖：

- 团队当前系统边界。
- Agent 与后端职责。
- 可靠性和发布流程。
- 新人前三个月交付。
- 技术债与学习支持。

问题不得索取保密信息，也不能只围绕福利。

### 29. 模拟面试官训练

两人一组。一人只能根据追问树继续提问，不能提示答案；另一人完成回答。交换角色后，比较“回答者错误”和“面试官追问质量”。

### 30. 合规审计

检查录音、转写和题目记录：

- 是否取得参与者同意。
- 是否含真实公司保密信息或个人数据。
- 是否设置访问与保留边界。
- 是否把模拟题误标成真实面试题。

## E. 发布作业

### 31. 面试能力档案

提交：

- 题目覆盖矩阵。
- 三次模拟成绩趋势。
- 前十错误类型。
- 证据索引。
- 仍不可对外宣称的能力。
