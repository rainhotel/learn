# 面试追问与表达

## 1. 线程池七个参数是什么？

推荐结构：先列参数，再说明它们不是独立的，重点强调线程数、队列和拒绝策略共同形成容量边界。

### 追问

- 核心线程默认会立即启动吗？
- keepAliveTime 是否能作用于核心线程？
- 为什么生产中需要自定义 ThreadFactory？

## 2. 线程池执行任务的流程是什么？

回答顺序：核心线程 -> 队列 -> 最大线程 -> 拒绝。

### 易错点

不要回答成“核心线程满了就创建非核心线程”。队列是否能接收任务是关键条件。

## 3. 线程池大小怎么设置？

高质量回答应包含：

- CPU/I/O 类型。
- 任务耗时与长尾。
- 目标吞吐和延迟。
- 下游 QPS、连接池和数据库容量。
- 队列与内存预算。
- 压测、指标和动态修正。

如果只背公式，面试官通常会继续问“供应商限流怎么办”“P99 很高怎么办”“连接池只有 20 怎么办”。

## 4. 为什么不建议直接使用 Executors 工厂方法？

不要绝对化。官方文档将工厂方法作为常见场景的便利配置。但在需要明确容量和过载行为的服务端业务中，部分工厂方法的默认无界队列或线程增长策略不利于显式治理，因此常直接构造并配置 `ThreadPoolExecutor`。

## 5. CallerRunsPolicy 有什么作用？

让提交线程执行任务，降低提交速度，形成简单反馈控制。

### 追问

- 如果提交线程是 Tomcat 请求线程会怎样？
- 如果提交线程是 Kafka Consumer 线程会怎样？
- 调用者持有锁时有什么风险？

## 6. execute 与 submit 的区别？

除任务类型和返回值外，重点讲异常观察：`submit` 将异常保存在 Future 中，不获取结果可能导致失败被忽略。

## 7. CompletableFuture 为什么要指定线程池？

避免慢 I/O 或特定业务任务污染公共池，实现业务隔离、容量管理和指标观测。

### 追问

- `orTimeout` 是否会停止底层 HTTP 请求？
- 多个异步阶段应该使用同一个池吗？
- 如何传递 traceId 和上下文？

## 8. 如何优雅关闭线程池？

讲两阶段关闭，并说明中断是协作式的。业务系统还需要停止入口、暂停消费和保证任务可恢复。

## 9. 动态线程池如何实现？

可以使用 setter 调整核心数、最大数和保活时间，但完整方案还包括配置校验、指标依据、变更审计、回滚、下游容量保护和避免抖动。

## 10. 项目中为什么使用线程池？

建议基于 NotifyFlow 回答：

> 通知渠道是慢 I/O，线程池用于隔离请求线程并限制单实例并发。任务先落库/MQ，因此线程池只承担执行资源边界，不承担可靠存储。短信和邮件分别隔离，并结合供应商限流、HTTP 超时和拒绝指标。参数通过响应时间、目标 QPS、连接池和压测调整。

## 11. 虚拟线程会替代线程池吗？

它降低阻塞任务的平台线程成本，但不会消除供应商 QPS、数据库连接、内存和 CPU 等边界。虚拟线程场景仍需要限流、Semaphore 或连接池控制稀缺资源。

## 12. 连续三层追问练习

### 题目 A：队列为什么设置 200？

1. 200 从哪些数据推导？
2. 排满时意味着多少等待时间？
3. 流量持续过载时怎么处理？

### 题目 B：为什么最大线程是 24？

1. 与供应商 QPS、响应时间有什么关系？
2. HTTP 连接池只有 10 会怎样？
3. 四个实例如何保证总并发？

### 题目 C：任务被拒绝怎么办？

1. 业务状态是否已经持久化？
2. 谁负责稍后重试？
3. 如何避免所有实例同时重试？
