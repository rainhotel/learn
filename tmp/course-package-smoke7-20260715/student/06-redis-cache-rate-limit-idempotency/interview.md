# Redis 面试追问

## 回答框架

每个问题先回答：

1. 业务需求和权威数据源。
2. Redis 数据结构与原子操作。
3. TTL、内存和并发边界。
4. 故障、复制和恢复。
5. 指标与替代方案。

## 基础题

### 1. 为什么 Redis 快？

内存访问、紧凑数据结构、高效事件循环和低开销协议共同作用。不要只答“单线程”：Redis 某些 I/O、持久化和后台任务可并行，关键命令执行模型和数据结构复杂度仍需具体分析。

### 2. String、Hash、ZSet 怎么选？

按访问模式、字段更新、排序范围、数据规模、TTL 和原子操作选择，不按对象名称选择。

### 3. 过期和淘汰有什么区别？

过期是 key 的生命周期；淘汰是内存达到上限后的资源策略。未过期 key 也可能被 eviction 删除。

### 4. Redis 事务能回滚吗？

没有 MySQL 式执行阶段回滚。`MULTI/EXEC` 保证排队命令连续执行；执行期某命令错误时其他命令仍可能执行。

### 5. Lua 有什么优缺点？

优点是服务端原子组合、减少往返；缺点是脚本阻塞命令执行，复杂脚本难测试和运维，必须短小有界。

## 缓存题

### 6. Cache Aside 如何保证一致性？

它不能证明强一致。常用更新数据库后删除缓存，并结合 TTL、失效重试、Outbox/CDC、版本和强一致绕缓存路径控制风险。

### 7. 穿透、击穿、雪崩？

分别是不存在数据持续 miss、单热点同时重建、大量 key 或服务同时失效。回答必须给出故障指标和恢复方案。

### 8. 热 key 怎么发现和处理？

结合命令统计、节点流量、应用埋点和 `--hotkeys`（LFU policy）定位；使用本地缓存、请求合并、合理分片或业务拆分。

### 9. 大 key 有什么危害？

网络和序列化放大、单命令阻塞、删除延迟、复制和 Cluster 迁移成本、fork COW 内存压力。

### 10. `@Cacheable` 能防击穿吗？

不能默认保证。需要确认 sync 行为、writer 原子性、锁粒度、异常缓存、TTL 和多实例并发。

## 限流与幂等题

### 11. 用 Redis 怎么限流？

根据需求选择固定窗口、滑动窗口、令牌桶；用单命令或 Lua保证原子性；设计租户维度、TTL、Redis 故障降级和监控。

### 12. `INCR` 和 `EXPIRE` 分开有什么问题？

客户端可能在两条命令间失败，形成无 TTL key。用 Lua 或事务化组合修复。

### 13. Redis 能完全保证幂等吗？

不能。过期、淘汰、故障转移和误删都会让 key 消失。最终幂等需要数据库唯一约束或外部系统幂等协议。

### 14. 幂等 key 的 value 存什么？

至少区分 PROCESSING、SUCCESS、FAILURE/UNKNOWN，并保存 owner、结果引用、创建时间和 schema version，而不是只存 1。

## 高可用题

### 15. RDB 和 AOF 怎么选？

从 RPO、RTO、性能、磁盘和可重建性选择。纯缓存可关闭持久化；关键短期状态需要明确允许的数据损失窗口。

### 16. 主从复制是强一致吗？

不是，默认异步。读副本可能陈旧，故障转移可能丢失已确认写。

### 17. `WAIT` 能保证不丢数据吗？

只能等待副本确认，不能把 Redis 变成共识系统；持久化、分区和故障转移仍有窗口。

### 18. Sentinel 做什么？

监控、通知、自动故障转移和主节点发现。quorum 判定故障，failover 还需多数授权。

### 19. Cluster 为什么是 16384 slots？

key 通过 CRC16 映射到槽，槽是分片与迁移单位。客户端缓存槽映射，hash tag 支持多 key 同槽。

### 20. Cluster 会丢写吗？

可能。节点间异步复制和分区存在 acknowledged write loss 窗口。

## 锁题

### 21. Redis 锁正确获取和释放？

`SET key unique-owner NX PX ttl`；释放时比较 owner 后删除，不能普通 `DEL`。

### 22. 有 watchdog 就绝对安全吗？

不。长 GC、网络分区、进程暂停、续期失败和时钟变化都可能让锁失效。关键下游需要 fencing token。

### 23. 为什么 NotifyFlow 任务不用 Redis 锁？

MySQL 任务表已经提供 lease、owner、version 和条件更新。额外 Redis 锁会制造双状态源和恢复复杂度。

## 故障题

### 24. 命中率 99%，P99 仍很高，怎么查？

检查大 key、热 key、慢命令、序列化、连接等待、网络、fork、AOF、THP、swap、复制同步和应用线程池，不被平均命中率误导。

### 25. Sentinel 切换后应用一直写旧主怎么办？

检查客户端是否使用 Sentinel discovery、拓扑刷新和重连；连接池是否缓存旧地址；DNS/配置是否写死；旧主是否被正确降级。

### 26. 幂等 key 被淘汰导致重复创建怎么办？

Redis 只应是快速路径。数据库唯一约束捕获冲突并返回已有结果，同时告警 eviction、调整内存/策略和 key 生命周期。

## 项目表达模板

> NotifyFlow 中 Redis 主要用于租户/供应商限流、模板缓存和短期幂等。最终任务状态和幂等结果仍在 MySQL。限流用 Lua 合并 INCR 与 TTL，避免客户端崩溃产生永久 key；模板更新通过数据库事务加 Outbox 驱动缓存失效；Redis key 被淘汰时数据库唯一约束继续兜底。我还设计了击穿、eviction、锁过期和 Sentinel 故障实验，用 P99、回源 QPS、evicted keys 和数据缺口评估，而不是只看命中率。
