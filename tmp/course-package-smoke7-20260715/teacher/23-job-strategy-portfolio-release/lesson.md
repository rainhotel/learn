# 第 23 章讲义：把求职和课程发布当成可观测迭代

## 一、先确定岗位组合

使用“一个主攻、一个相邻、一个行业备选”：

- 主攻：Java 后端，强调并发、事务、缓存、消息、排障和分布式。
- 相邻：Agent/AI 应用后端，强调 Java 服务、RAG、Tool、评测、安全和成本。
- 行业备选：先进制造数字化，强调系统集成、可追溯、权限、任务可靠性和长期运维。

这不是根据想象判断市场。每周必须重新采样公开 JD，并保存链接、日期和原文摘要。

## 二、JD 研究流程

```text
采样 -> 去重 -> 字段编码 -> 关键词归类
-> 必需/加分/业务域 -> 证据映射 -> 缺口排序
```

同一职位的多个镜像页面只算一个样本。样本量不足时只能形成“观察”，不能形成市场频率、薪资或排名结论。

## 三、匹配评分不是录用概率

建议 100 分内部排序：Java 25、数据/缓存/MQ 20、Agent/RAG 20、容器分布式 15、业务与事实 10、城市/时间 10。

分数用于安排准备时间，不代表录用概率。硬性学历、毕业时间、实习周期、城市和安全资质需要单独设 veto 字段。

## 四、一份事实主简历，多个摘要

事实、时间、项目边界和证据只维护一份。岗位版本只能调整：

- 摘要顺序。
- 相关技能的展示顺序。
- 项目 bullet 的选择。
- 与 JD 对应的可验证关键词。

不能为了匹配岗位把课程设计改成实习经历，也不能把 Pending 实验写成线上成果。

## 五、小批次投递

每批选择相似岗位，固定简历版本和时间窗口。记录：岗位、版本、匹配分、回复、笔试、面试、失败阶段和反馈。一次修改一个主要变量，否则无法判断变化来自何处。

不要用回复率评价个人价值。它受岗位时效、HC、学校、城市、时间和竞争影响；数据只用于调整目标、材料和准备路径。

## 六、反馈回写课程

每个真实追问映射到：

```text
question -> weak answer -> missing evidence
-> chapter -> exercise/lab -> next simulation
```

如果同一问题重复出现，应升级为章节练习、面试追问或勘误，而不是只记在聊天里。

## 七、作品集结构

最低作品集包括：

1. 一页项目介绍和系统图。
2. 可复现启动说明与版本清单。
3. 核心代码或最小实验。
4. 原始输出、指标和数据正确性报告。
5. 故障时间线和边界说明。
6. RAG/Agent 评测、安全与权限说明。
7. 事实简历、5/15/45 分钟答辩稿。

设计稿、模型实验和真实服务结果必须使用不同证据标签。

## 八、文档课程产品化

课程可售卖不等于文件很多。学习者必须知道：为什么学、先学什么、如何运行、如何评分、失败后去哪排查、何时算完成。

每章发布前检查：八件套、来源、答案隔离、实验环境、原始证据、作业 rubric、Teach-back、版权、版本和勘误入口。

## 九、版本与发布门禁

- Draft：内容可读，但实验或教学验证不足。
- Lab Verified：本章承诺的实验已按固定环境运行。
- Teach Verified：学习者完成作业和试讲，依据反馈修订。
- Release Candidate：全课程导航、依赖、样章、许可证/版权、安装和勘误通过审计。
- Released：发布候选经陌生学习者完整试用并关闭阻断问题。

一个章节通过不代表全课程发布。任何关键实验 Pending 时，销售页必须明确范围。

## 十、安全与隐私

投递台账、面试反馈和课程样例不得暴露身份证、手机号、私人邮箱、企业 Secret、客户数据或未经授权的实习材料。公开证据需要脱敏，并确认第三方资料引用和许可证。

## 十一、当前证据边界

实时 JD 页面尚未形成有效样本；课程仍是内部 Alpha。没有真实投递和陌生学习者完整试用前，不得声称课程能保证 offer、命中面试题或达到市场转化率。
