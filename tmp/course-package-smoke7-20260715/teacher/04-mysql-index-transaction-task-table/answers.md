# 练习答案与评分标准

## A. 索引

1. 聚簇索引包含行数据；二级索引包含索引列和主键，必要时回表。
2. 回表是根据二级索引主键再查聚簇记录；查询列全部在索引中是覆盖访问。
3. tenant、tenant+status、tenant+status+created_at、完整四列前缀。
4. 空间、写维护、优化器复杂度和写入延迟增加。

## B. EXPLAIN

1. `key` 是实际使用索引；`rows` 是估计扫描/产生行数；`filtered` 是过滤比例；TREE 直接显示扫描、过滤、排序和覆盖。
2. 可能扫描大量行、回表、排序、统计信息不准、下游资源慢或结果集过大。
3. 对相同谓词分别选择只含摘要列和需要 payload 的查询，比较 Covering index 与 row lookup，并记录实际时间和扫描行数。

## C. 事务

1. RR 通常在事务内复用首次一致性读快照；RC 每次一致性读获取新快照。
2. 快照读读取历史版本且不以锁定当前行作为目标；FOR UPDATE 是锁定读，服务并发修改/领取。
3. 数据库无法撤销已经发给外部供应商的副作用，需要幂等、Outbox、状态机和补偿。
4. 可能读取未提交数据，产生脏读。

## D. 领取

短事务中 `SELECT ... FOR UPDATE SKIP LOCKED` 找任务，随后更新 SENDING、worker、lease 和 version，提交后再调用外部服务。

不能持锁调用供应商，因为慢 I/O 会延长锁生命周期、阻塞其他 worker 并放大死锁。

lease 解决 worker 崩溃后的重新领取；version/owner 条件防止过期 worker 覆盖新 worker。

供应商调用必须有幂等 key 或查询/对账协议；不能仅凭本地数据库回滚推断外部未发生。

## E. 死锁

一个事务锁 1 等待 2，另一个锁 2 等待 1。捕获 1213 后回滚并以有限次数、退避、全事务重试；统一访问顺序、缩短事务、合适索引可减少概率。

死锁主要由锁顺序和写竞争形成，隔离级别会影响读锁/间隙锁，但不能简单说“某隔离级别必然无死锁”。

## 加分题

OFFSET 深分页需跳过大量结果，越深越贵；seek 根据上次排序键继续，通常更稳定，但需要稳定唯一排序键且不适合随意跳页。

## 评分

- 90-100：可进入任务领取系统设计答辩。
- 80-89：补做 EXPLAIN 或隔离级别实验。
- 60-79：重跑 SQL 并画锁/快照图。
- 低于 60：返回索引与事务基础。
