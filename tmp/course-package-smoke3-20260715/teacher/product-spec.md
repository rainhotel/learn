# 《Java 后端与 Agent 工程实战》课程产品规格

## 1. 产品定位

这不是知识点合集，而是一套以真实工程证据为核心的暑期求职课程。

目标学习者：

- Java 基础零散，希望建立后端主线的学生。
- 目标岗位为互联网中大厂 Java 后端、Agent/AI 应用后端或先进制造数字化研发。
- 能使用 AI 辅助完成全栈任务，但需要补齐并发、数据库、消息、可观测性、容器和分布式基础。
- 希望把学习成果转化为简历项目、面试表达、试讲内容和可公开作品。

不适合：

- 只想背面试答案、不愿运行实验的人。
- 希望几天内速成全部后端与 Agent 技术的人。
- 希望把未做过的技术包装成实习事实的人。

## 2. 核心承诺

完成课程并通过发布门槛后，学习者应能够：

1. 以 Java 21 为主语言完成后端业务、并发与故障恢复代码。
2. 解释 MySQL、Redis、Kafka、Spring 事务和 JVM 机制，而不是只会调用 API。
3. 构建 NotifyFlow 可靠通知平台，形成可演示、可压测、可排障的项目证据。
4. 为 RAG/Agent 系统提供可靠的 Java 后端、工具调用、权限、审计和可观测性能力。
5. 使用 Docker、Kubernetes 入门能力和多实例设计完成部署与系统设计说明。
6. 面对项目追问时提供代码、实验、日志、指标、SQL、JFR 或报告，而不是编造线上数字。
7. 用 5 分钟、15 分钟和 45 分钟三个粒度教会别人一个主题。

课程不承诺 offer，也不承诺固定 QPS、薪资或面试原题命中率。

## 3. 教学主项目

主项目统一使用 NotifyFlow：可靠消息通知与 Agent 工具执行平台。

项目主线：

```text
创建通知任务
-> MySQL 任务表与幂等记录
-> Transactional Outbox
-> Kafka 消费与重试预算
-> Provider 调用
-> UNKNOWN/DLT/对账/安全重放
-> Metrics/Logs/Trace/JFR
-> RAG/Agent 事故助手
-> Docker/Kubernetes/多实例部署
```

Agent 只负责证据检索、异常聚类、摘要和建议。重放、清队列、扩容、权限变更等高风险动作必须由确定性控制面、审批与审计约束。

## 5. 学习路径

### 阶段 A：Java 与数据基础

1. 线程池与异步通知任务。
2. HashMap 与集合选型。
3. JMM、volatile 与 synchronized。
4. MySQL 索引、事务与任务表设计。

### 阶段 B：可靠后端主链路

5. Spring 事务、AOP 代理与业务边界。
6. Redis 缓存、限流与短期幂等。
7. Kafka 可靠消息与 Transactional Outbox。
8. 重试、DLT、UNKNOWN、对账与恢复控制面。
9. 可观测性、压测与故障注入。

### 阶段 C：生产与平台工程

10. JVM 内存、GC 与排障。
11. 网络、连接池、超时和容量。
12. Docker、测试与部署。
13. 系统设计与项目答辩。

### 阶段 D：Agent 工程

14. LLM、Transformer、推理与上下文原理。
15. 企业文档处理、切分与 ingestion。
16. 混合检索、rerank 与向量数据库工程。
17. RAG 评测、引用与安全。
18. Tool、Memory、Agent Runtime 与可靠执行。

### 阶段 E：多机分布式工程

19. 多实例任务领取、租约、幂等、限流、补偿和可观测性。

### 阶段 F：求职发布

20. 简历事实台账与证据表达。
21. Java、项目与系统设计面试。
22. 算法、Teach-back 与陌生读者测试。
23. 岗位策略、作品修订与发布。

## 6. 单章标准交付物

每章优先复用以下八件套：

| 文件 | 学习者得到什么 | 发布检查 |
|---|---|---|
| `README.md` | 定位、状态、退出标准 | 不夸大完成度 |
| `lesson.md` | 可独立阅读的讲义 | 原理、反例、边界齐全 |
| `project-application.md` | NotifyFlow 真实应用 | 有 DDL/API/状态机或时序 |
| `lab/` | 可运行实验 | 版本、命令、输出、证据 |
| `exercises.md` | 作业与评分题 | 覆盖理解、设计、排障 |
| `answers.md` | 参考答案与评分标准 | 不提供虚假经历模板 |
| `interview.md` | 面试回答与追问 | 有机制、场景、边界 |
| `teach-back.md` | 试讲脚本 | 5/15/45 分钟版本 |
| `sources.md` | 来源与核验状态 | 一手资料优先 |

稳定知识进入章节，学习过程和失败记录进入 `02-journal/`。

## 7. 每章学习闭环

```text
预习问题
-> 阅读讲义
-> 不看答案复述机制
-> 先写失败测试或实验假设
-> 运行并保存原始证据
-> 应用到 NotifyFlow
-> 完成练习和面试追问
-> 5/15/45 分钟 Teach-back
-> 根据听众问题修订
```

学习者不得跳过实验直接背参考答案。

## 8. 评分体系

单章满分 100：

| 维度 | 分值 |
|---|---:|
| 原理与适用边界 | 20 |
| 实验可重复性 | 20 |
| NotifyFlow 工程应用 | 20 |
| 故障、反例与数据正确性 | 15 |
| 面试表达 | 10 |
| Teach-back | 10 |
| 来源与诚实边界 | 5 |

判定：

- 90-100：可以进入发布候选。
- 80-89：可以用于求职复习，仍需修订。
- 70-79：理解不稳定，需要补实验或反例。
- 70 以下：不得在简历或公开课程中宣称掌握。

## 9. 状态门禁

| 状态 | 必须满足 |
|---|---|
| Research | 问题、范围和一手来源已确定 |
| Draft | 八件套内容初稿齐全 |
| Lab Verified | 指定版本真实运行，原始输出可复核 |
| Teach Pending | 等待学习者真实试讲和作业 |
| Teach Verified | 学习者完成作业和试讲，并依据反馈修订 |
| Release Candidate | 实验、教学、复现、版权和交付门禁均通过 |
| Released | 陌生读者验证、版权检查和版本归档完成 |

`Partial Lab` 只用于描述部分实验已有证据，不是独立发布状态。静态检查、模型模拟和真实基础设施实验必须分别标记，不能相互替代。

## 10. 证据等级

从弱到强：

1. AI 生成或个人理解草稿。
2. 官方文档核验。
3. 源码、配置或脚本静态检查。
4. 确定性模型实验。
5. 本地真实组件运行。
6. 故障注入、时间线和数据正确性验证。
7. 陌生环境复现与学习者独立完成。

简历量化结果至少达到第 5 级，并注明环境。课程发布结论应尽量达到第 6-7 级。

## 11. 诚实与合规规则

- 大烨实习只写真实做过的职责和技术。
- MySQL、Redis、MQ、RAG 等新增能力应写为独立工程化重构项目。
- 未运行的实验不得写“通过”“验证”“优化了 X%”。
- 模拟结果不得伪装成线上生产数据。
- 压测结果必须注明机器、版本、数据、时间和限制。
- 复制资料需要保留来源，不直接搬运受版权保护的大段内容。
- Agent 不得绕过权限、审批和审计执行高风险操作。

## 12. 建议暑期节奏

具体每日任务、周测、Teach-back 和复盘模板见 `student-workbook.md`。
岗位采样、事实台账、简历和面试交付模板见 `job-readiness-pack.md`。

建议 10 周，每周 20-25 小时：

| 周 | 主线 | 周末产出 |
|---|---|---|
| 1 | Java 集合、并发基线 | 章节测验与线程池实验 |
| 2 | JMM、MySQL | SQL 报告与 Teach-back |
| 3 | Spring 事务 | 事务边界实验与项目设计 |
| 4 | Redis | 限流、缓存、幂等实验 |
| 5 | Kafka/Outbox | 可靠消息时间线 |
| 6 | 重试、DLT、对账 | 恢复控制面演示 |
| 7 | 可观测性、压测、JFR | Dashboard/压测/排障报告 |
| 8 | LLM、Embedding、RAG | RAG 服务与评测集 |
| 9 | Agent、Docker、K8s | 工具执行与部署演示 |
| 10 | 简历、算法、模拟面试 | 求职作品包与最终试讲 |

若实验环境被阻塞，继续做讲义、测试设计、零依赖实验和证据整理，但不能降低发布门槛。

## 13. 学习者最终作品包

毕业时应交付：

- NotifyFlow 源码与一键启动说明。
- 架构图、核心时序图和数据模型。
- 事务、Redis、MQ、恢复和可观测性实验报告。
- k6/JFR/数据库或消息故障证据。
- RAG 评测集与 Agent 工具安全说明。
- Docker/Kubernetes 部署与回滚说明。
- 一页项目简历、五分钟项目介绍、十五分钟技术试讲。
- 错题、面试追问和阶段复盘。

## 14. 教师交付包

具体授课、评分、术语、版本、引用和发布操作见 `instructor-editorial-guide.md`。

可售卖版本应区分：

- 学习者版：讲义、实验说明、练习、项目任务和评分表。
- 教师版：答案、故障注入脚本、试讲提示、常见误区和评分锚点。
- 证据包：固定版本、环境、原始输出、报告和已知限制。
- 更新日志：每次版本变化、来源更新和破坏性调整。

答案不应与练习默认放在同一阅读流程中，授课时按阶段解锁。
