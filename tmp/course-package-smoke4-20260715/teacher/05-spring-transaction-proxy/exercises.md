# 章节练习

总分 100 分。达到 80 分且实验题不低于 60%，才进入项目答辩。

## A. 代理机制（20 分）

1. 为什么只写 `@Transactional` 不一定产生事务？列出三个必要条件。（6 分）
2. 解释同类自调用绕过事务的完整调用链。（6 分）
3. 比较 JDK 动态代理和 CGLIB 类代理，并指出它们是否能解决自调用。（4 分）
4. 为什么不建议把 `AopContext.currentProxy()` 作为常规修复？（4 分）

## B. 回滚规则（20 分）

1. Spring 声明式事务的默认回滚规则是什么？（4 分）
2. 一个事务方法插入数据后抛出 `IOException`，未配置 `rollbackFor`。预测结果并解释。（4 分）
3. `rollbackFor = Exception.class` 有什么收益和风险？请给出更合适的异常设计。（6 分）
4. 为什么事务方法中 `catch (Exception) { log.error(...) }` 可能造成数据错误？至少说明两种结果。（6 分）

## C. 传播行为（20 分）

1. 区分逻辑事务和物理事务。（4 分）
2. 画出 `REQUIRED` 内层标记 rollback-only 后产生 `UnexpectedRollbackException` 的过程。（6 分）
3. `REQUIRES_NEW` 为什么可能耗尽连接池？假设 20 个并发线程，每个外层事务都调用一次内层新事务，估算最坏同时连接需求。（6 分）
4. `NESTED` 与 `REQUIRES_NEW` 的核心差异是什么？（4 分）

## D. 线程与外部副作用（20 分）

1. 新线程为什么不自动继承传统 Spring 事务？（4 分）
2. `@Async` 方法需要写数据库时，应该如何定义事务边界？（4 分）
3. 为什么数据库事务不能回滚已经发送的短信或 Agent 工具执行？（4 分）
4. 设计一个不在事务中调用供应商、又能最终完成通知的流程。（8 分）

## E. NotifyFlow 故障设计（20 分）

1. 任务和 Outbox 事件为什么要在同一个事务中插入？（4 分）
2. Outbox 消息发送成功，但进程在标记 `PUBLISHED` 前崩溃，会发生什么？如何处理？（4 分）
3. 供应商返回超时，但短信可能已经发出。为什么不能直接重试？给出恢复协议。（6 分）
4. 旧 worker lease 过期后，新 worker 已领取任务；此时旧 worker 返回成功。如何防止它覆盖新状态？（6 分）

## 实验作业（必做）

实现并保存以下测试输出：

1. 运行时异常默认回滚。
2. 检查异常默认提交与 `rollbackFor` 回滚对比。
3. 自调用与跨 Bean 调用对比。
4. `REQUIRES_NEW` 独立提交。
5. `UnexpectedRollbackException`。
6. 新线程事务状态。

提交物：

- 测试源码。
- RED 与 GREEN 输出。
- 每个测试的数据库最终状态。
- 一页实验结论，说明哪些是 Spring 保证、哪些只是当前代理类型观察。

## 加分题

### 1. 连接池实验（10 分）

把连接池最大连接数设为并发线程数，构造外层事务同时调用 `REQUIRES_NEW`，观察等待或超时。给出容量模型和替代设计。

### 2. Agent 工具执行（10 分）

设计一个创建工单工具的可靠执行协议，要求处理超时、重复调用、结果查询、人工补偿和租户权限。
