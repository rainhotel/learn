# Teach-back：把 Spring 事务讲给别人

## 教学目标

听众在课程结束后能够回答：

1. 为什么注解不等于事务？
2. 自调用为什么绕过代理？
3. 哪些异常默认回滚？
4. `UnexpectedRollbackException` 如何形成？
5. 为什么供应商调用不能依赖数据库回滚？

## 5 分钟版本

### 0:00-0:40 真实问题

提出场景：事务中插入任务、发送短信，然后数据库更新失败。问听众“短信会被回滚吗？”

### 0:40-2:00 代理机制

画出：

```text
Caller -> Proxy -> TransactionInterceptor -> Target -> DB
```

说明 `@Transactional` 是元数据，只有经过代理的调用才会被拦截。用 `this.createOne()` 解释自调用。

### 2:00-3:00 回滚与传播

- 运行时异常默认回滚。
- 检查异常默认不回滚。
- `REQUIRED` 可以共享一个物理事务。
- 内层 rollback-only 会让外层提交得到 `UnexpectedRollbackException`。

### 3:00-4:20 工程边界

数据库事务不能撤销 HTTP、短信、MQ 和 Agent 工具执行。长事务还会占用连接和锁。

### 4:20-5:00 NotifyFlow 方案

短事务写任务和 Outbox，事务外调用供应商，短事务确认状态，用幂等和对账处理重复与结果未知。

## 15 分钟版本

### 第一部分：错误直觉（2 分钟）

- 展示“大事务发送短信”的伪代码。
- 让听众预测数据库失败后的短信状态。
- 明确本节要解决的是资源边界，而不仅是注解语法。

### 第二部分：代理调用链（4 分钟）

画调用者、代理、拦截器、事务管理器和目标对象。

演示两条路径：

```text
external -> proxy -> transactional method
target method -> this.inner() -> target method
```

解释接口代理、类代理的差异和共同的自调用边界。

### 第三部分：异常和传播（4 分钟）

用四个结果对比：

| 场景 | 结果 |
|---|---|
| RuntimeException | 默认回滚 |
| checked exception | 默认提交 |
| checked + rollbackFor | 回滚 |
| inner REQUIRED rollback-only | 外层提交点抛异常 |

再画两个逻辑事务共享一个物理事务，解释 `UnexpectedRollbackException`。

### 第四部分：NotifyFlow 设计（4 分钟）

画任务创建、Outbox、MQ、Worker、供应商、确认事务。

必须讲出：

- 每个数据库事务在哪里开始和结束。
- 哪一步允许重复。
- 幂等键放在哪里。
- 供应商结果未知如何对账。

### 第五部分：总结（1 分钟）

用一句话收束：

> Spring 事务解决受管理资源内的原子性；可靠业务还需要正确代理入口、明确异常语义、短事务和跨系统恢复协议。

## 最容易被追问的点

1. 类代理不是能拦截类方法吗，为什么自调用仍不行？
2. 外层已经捕获异常，为什么事务还回滚？
3. `REQUIRES_NEW` 为什么需要额外连接？
4. `NESTED` 为什么不等于独立提交？
5. `readOnly` 是否绝对禁止写？
6. `@Async` 和事务同时存在时，事务在哪个线程？
7. Outbox 为什么仍然可能重复消息？
