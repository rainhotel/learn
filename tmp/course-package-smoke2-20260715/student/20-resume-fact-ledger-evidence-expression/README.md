## 核心原则

简历不是技术愿望清单，而是可以在面试中逐句举证的事实索引。

大烨实习只允许写真实发生的职责、技术、环境和结果。课程中新学的 MySQL、Redis、消息队列、RAG、Agent、Docker、Kubernetes 等内容，如果没有在该实习中真实使用，必须写入“独立工程项目”“课程实验”或“设计研究”，不得移入实习经历。

## 核心问题

1. 如何把经历、动作、结果和证据拆成可审计事实？
2. 如何区分实习事实、独立项目、课程实验和设计方案？
3. STAR/CAR 怎样压缩成一条不夸大、可追问的简历 bullet？
4. 没有生产 QPS 和商业收入时，怎样合法量化工程成果？
5. Java 后端、Agent 后端和先进制造数字化三类简历应如何共用同一事实源？
6. ATS 关键词如何来自目标 JD，而不是机械堆词？
7. 教育、技能、项目和实习经历应如何排序与取舍？
8. 如何通过反向追问发现虚构、因果跳跃和证据不足？

## 退出标准

- 每条简历 bullet 都有 `claim_id`，能追溯到事实台账和证据。
- 能明确说明“我做了什么、没有做什么、团队做了什么”。
- 大烨实习与独立工程项目完全分开，没有技术栈迁移或结果挪用。
- 每个数字都有口径、样本、环境、日期和原始材料；否则删除数字或降级措辞。
- 能基于同一事实主库生成 Java 后端、Agent 后端、制造业数字化三版简历。
- 技能栏只保留能被追问的技术，且与正文证据相互印证。
- 通过 30 分钟逐句压力测试，不能回答的句子已删除、降级或补证据。
- 能在 90 秒内讲清一段经历，并在 5 分钟内展开关键取舍和失败。
