# 第 22 章讲义：从刷题到可验证的问题求解能力

## 1. 面试真正观察什么

一道算法题不是只看最终代码。面试官通常在观察六件事：

1. 是否主动澄清输入、输出、规模、重复值、顺序和异常约束。
2. 是否先建立正确的朴素解，再找到性能瓶颈。
3. 是否能用数据结构保存“以后仍需知道的状态”。
4. 是否能解释不变量、正确性和复杂度。
5. 是否能写出完整 Java 代码并主动测试。
6. 遇到提示或 bug 后，是否能定位原因并继续推进。

因此，本章的最小训练单位不是“AC 一题”，而是一张可复核的题目证据卡。

## 2. 题目证据卡

每个首次解题槽位使用下列字段：

```text
problem_id:
source_and_version:
date_started:
constraints_rephrased:
first_attempt_minutes:
first_attempt_result: independent | hinted | reviewed | unfinished
brute_force:
optimized_idea:
invariant_or_state:
time_complexity:
space_complexity:
tests:
mistake_tags:
code_or_commit:
next_review_date:
review_history:
```

`hinted`、`reviewed` 和 `unfinished` 都是有效学习记录，但不能伪装为首次独立完成。题量统计与能力统计必须分开。

## 3. 九模块、96 个首次解题槽位

### 3.1 难度结构

建议每个模块采用约 `30% 基础 + 50% 中等 + 20% 综合`。这里的难度只用于组织课程，不同平台标签不能直接比较。

选题满足以下约束：

- 同一模板至少有“直接应用、边界变化、跨模板组合”三种题。
- 同一题的再次求解属于复习，不增加首次题量。
- 换题时保留原卡并记录原因，避免只留下顺利样本。
- 题单不绑定某一家平台；发布课程时遵守题目版权，只引用标题、链接和自写解析。

### 3.2 模块能力矩阵

| 模块 | 识别信号 | 关键不变量/状态 | Java 风险 |
|---|---|---|---|
| 数组/字符串 | 连续存储、原地修改 | 已处理前缀合法 | 下标、复制、字符编码 |
| 哈希/前缀/窗口 | 计数、快速查找、连续区间 | map 与当前区间一致 | null、装箱、哈希退化 |
| 链表/栈/队列 | 顺序重连、嵌套、最近未决 | 指针不丢、栈语义 | 空指针、头尾节点 |
| 二分 | 有序或答案单调 | 答案始终位于闭/开区间 | 中点溢出、死循环 |
| 树/堆 | 层次、递归子问题、Top K | 子树返回值含义 | 递归深度、比较器溢出 |
| 图/并查集 | 关系、依赖、连通 | 访问颜色、集合代表 | 重复边、孤立点、环 |
| 回溯 | 枚举组合、排列、路径 | path 对应当前决策层 | 撤销遗漏、重复结果 |
| 动态规划 | 重叠子问题、最优子结构 | `dp` 的精确定义 | 初始化、遍历顺序 |
| 贪心/区间 | 局部选择、覆盖与调度 | 已选解不妨碍最优性 | 缺少证明、排序边界 |

## 4. Java 数据结构选择

| 需求 | 首选 | 备注 |
|---|---|---|
| 固定长度、按下标访问 | `int[]` / `long[]` | 数值累计优先评估 `long` |
| 动态顺序表 | `ArrayList<E>` | 中间插入删除不是 O(1) |
| 栈 | `ArrayDeque<E>` | 不使用旧式 `Stack`；禁止放 null |
| FIFO 队列 | `ArrayDeque<E>` | `offer/poll/peek` 更适合边界处理 |
| 优先队列 | `PriorityQueue<E>` | 默认小顶堆；比较器避免相减溢出 |
| 键值/计数 | `HashMap<K,V>` | 说明期望 O(1)，不要说绝对 O(1) |
| 去重 | `HashSet<E>` | 自定义对象需正确 equals/hashCode |
| 有序键 | `TreeMap<K,V>` | 操作为 O(log n) |
| 图邻接表 | `List<List<Integer>>` | 稀疏图常用；先创建每个顶点容器 |

比较器应写成：

```java
Comparator<int[]> byEnd = (a, b) -> Integer.compare(a[1], b[1]);
```

不要写 `a[1] - b[1]`，因为差值可能溢出并破坏比较器合同。

## 5. 复杂度不是背结论

### 5.1 推导步骤

1. 定义输入规模，例如数组长度 `n`、顶点数 `V`、边数 `E`。
2. 计算最坏情况下核心操作执行次数。
3. 明确数据结构操作的假设和摊还语义。
4. 分开写辅助空间、输出空间和递归栈。
5. 检查 Java 隐藏成本：子串复制、装箱、对象分配、排序和哈希。

### 5.2 常见误判

- 两层循环不一定是 O(n²)：双指针总移动次数可能只有 O(n)。
- 单层循环不一定是 O(n)：循环内排序、复制字符串或堆操作仍有额外成本。
- 回溯不能统一写 O(2^n)，应说明搜索树分支、深度以及构造结果成本。
- 图遍历是 O(V+E) 的前提是邻接表并且每个顶点、边只处理常数次。
- HashMap 查找通常写“期望 O(1)”，需要承认哈希质量和冲突假设。

## 6. 正确性解释的四种工具

### 6.1 循环不变量

适合双指针、窗口、二分和原地数组。完整解释包含：初始化成立、每轮保持、终止时推出结果。

### 6.2 递归语义与归纳

先用一句话定义函数返回值，例如“`dfs(node)` 返回以 node 为根的最大深度”。再说明空节点、左右子问题和组合规则。

### 6.3 状态与转移

动态规划必须先写：

```text
dp[i] 精确代表什么
从哪些已知状态转移
基础状态为什么正确
遍历顺序为何保证依赖已计算
最终答案位于哪里
```

### 6.4 交换论证

贪心需要证明：任意最优解若没有采用当前选择，可以交换成采用该选择且不变差。只有“每次选最大/最小看起来最好”不构成证明。

## 7. 高频模板与边界

### 7.1 左闭右开二分

```java
static int lowerBound(int[] a, int target) {
    int left = 0;
    int right = a.length;
    while (left < right) {
        int mid = left + (right - left) / 2;
        if (a[mid] < target) {
            left = mid + 1;
        } else {
            right = mid;
        }
    }
    return left;
}
```

不变量是答案始终位于 `[left, right)`；返回值可能等于数组长度。

### 7.2 可变滑动窗口

```text
for right 扩展窗口:
    纳入 right
    while 窗口违反约束:
        移出 left
        left++
    使用当前合法窗口更新答案
```

关键不是背循环，而是精确定义“窗口合法”以及 map/计数与 `[left,right]` 的一致性。

### 7.3 BFS

```java
ArrayDeque<Integer> queue = new ArrayDeque<>();
boolean[] visited = new boolean[n];
queue.offer(start);
visited[start] = true;
while (!queue.isEmpty()) {
    int u = queue.poll();
    for (int v : graph.get(u)) {
        if (!visited[v]) {
            visited[v] = true;
            queue.offer(v);
        }
    }
}
```

在入队时标记可以避免同一顶点被重复入队。若题目需要最短步数，应明确层数或距离数组。

### 7.4 回溯

```text
backtrack(state, start):
    若达到输出条件，复制 path
    for 每个可选项:
        过滤非法或重复选择
        选择
        递归
        撤销选择
```

输出时必须复制可变 path；排序去重时要区分“同层重复”和“跨层重复”。

### 7.5 并查集

需要掌握路径压缩和按大小/秩合并。面试中应说明它适合动态合并与连通性查询，不适合直接回答最短路径。

## 8. 从题目到代码的 40 分钟协议

| 时间 | 行为 | 产出 |
|---:|---|---|
| 0-5 分钟 | 复述问题、问约束、手算样例 | 明确合同与边界 |
| 5-10 分钟 | 给出朴素解 | 正确性基线与瓶颈 |
| 10-15 分钟 | 选择结构、写不变量 | 优化方案与复杂度 |
| 15-30 分钟 | 编码 | 完整、可编译的 Java 方法 |
| 30-36 分钟 | dry run 与测试 | 发现下标、状态和溢出错误 |
| 36-40 分钟 | 总结与追问 | 复杂度、替代方案、扩展 |

时间不是硬性评分；卡住时应说明已知事实、尝试和最小问题，而不是沉默猜测。

## 9. 测试与边界矩阵

每题至少从下列维度选择适用项：

- 结构：null 是否允许、空输入、单元素、两元素。
- 值域：零、负数、最大/最小整数、累计和溢出。
- 分布：全相同、严格递增/递减、重复值、答案不存在。
- 位置：答案在开头、结尾、中间、覆盖全部。
- 图树：孤立点、单链、平衡/极度倾斜、环、重复边、不连通。
- 状态：第一次就满足、永不满足、多种最优解。
- 规模：最小规模和约束上界；必要时进行随机差分测试。

### 9.1 差分测试

保留一个只适用于小规模的朴素解，随机生成输入，将优化解与朴素解输出比较。差分测试不能替代证明，但能高效发现边界错误。

### 9.2 性质测试

例如排序结果应满足“非递减 + 元素多重集合不变”；并查集连通关系应具有自反、对称和传递性质。

## 10. 错因标签

| 标签 | 含义 | 修复动作 |
|---|---|---|
| `contract` | 没问清输入输出 | 先写三条合同 |
| `recognition` | 未识别结构/模板 | 与两个近邻题做对比卡 |
| `invariant` | 状态定义含糊 | 用自然语言写初始化/保持/终止 |
| `implementation` | 思路对但 Java 出错 | 无补全重写最小模板 |
| `boundary` | 空集、重复、溢出等失败 | 增补测试矩阵 |
| `complexity` | 复杂度推导错误 | 写操作次数而非直接写 O 符号 |
| `explanation` | 会写但讲不清 | 录制 5 分钟 Teach-back |
| `transfer` | 原题会，变式不会 | 安排跨模板变式 |

只记录“粗心”没有诊断价值。一个失败可以有多个标签，但必须选一个主因。

## 11. 间隔复习协议

默认复习点为首次学习后的第 1、3、7、14、30 天。每次复习分级：

- A：无提示完成，代码和解释均通过。
- B：无提示得到核心方案，但实现或边界需要小修。
- C：需要关键词提示或无法完成。
- D：看答案后仍无法解释不变量。

调度规则：

- A：进入下一间隔。
- B：下一次提前到 2-3 天内，并重写失败片段。
- C：次日重做，再安排一个同模板变式。
- D：返回概念讲义，先做最小示例，再重启复习链。

复习必须闭卷开始。先看旧代码再重写只能算 review，不能记为 recall pass。

## 12. 白板与无补全编码

每周至少选择一题，在纯文本编辑器、纸面或共享编辑器完成：

1. 口述合同和例子。
2. 写方法签名与核心数据结构。
3. 分块编码，持续解释不变量。
4. 手工 dry run，不依赖运行器立即纠错。
5. 最后才编译和运行测试。

证据应同时保留原始版本和修复版本。只保存最终漂亮代码会丢失诊断价值。

## 13. Teach-back 与陌生读者测试

Teach-back 不是把题解朗读一遍。合格的教学输出需要：

- 先给失败的直觉或朴素解，让读者理解为什么需要新结构。
- 明确定义不变量、状态和适用边界。
- 用一张表对比近邻模板，例如固定窗口与可变窗口。
- 让读者完成一个“非同题复现”的迁移任务。
- 通过读者行为判断讲义是否有效，而不是只问“听懂了吗”。

陌生读者测试时，作者不能实时补充解释。记录读者停顿位置、错误理解、任务结果和所用时间，再根据证据修改文档。

## 14. 模拟面试评分

每轮使用 100 分：

| 维度 | 分值 |
|---|---:|
| 澄清与样例 | 10 |
| 朴素解与优化推导 | 15 |
| 数据结构与不变量 | 20 |
| Java 实现 | 20 |
| 测试与修错 | 15 |
| 复杂度与正确性 | 10 |
| 沟通与协作 | 10 |

分数必须由评分表、原始记录和评审人共同支持。当前没有已完成模拟，不应写任何个人分数或通过率。

## 15. 学习看板与发布证据

看板至少分开显示：

```text
planned_first_attempts
attempted
independent_pass
hinted_or_reviewed
reviews_due
recall_pass_by_interval
whiteboard_sessions
teach_back_sessions
stranger_tests
mock_interviews
```

“完成 96 题”只说明首次题槽有记录，不能自动推出面试通过。对外表述应优先使用可核验动作，例如：

> 建立 96 题 Java 算法训练与间隔复习体系；题量、独立完成状态、边界测试和模拟面试结果均保留可追溯证据。

只有实际完成后才能使用这句话。未完成期间应写“正在建设”或 Pending。
